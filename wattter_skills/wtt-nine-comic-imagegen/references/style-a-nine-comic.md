# 风格 A：9号漫画（完整参考）

中文恶搞科普竖版长图——手绘黑白人物、荒诞表情、一本正经用最俗的日常琐事解释最高深的概念。

---

## 核心原则

**比喻铁律：用最俗的东西解释最玄的东西。** 这是本风格的幽默核心。解释任何概念时，比喻必须从日常生活的最低处取材——菜市场砍价、蹲马桶刷手机、煮泡面翻车、相亲尬聊、挤地铁抢座、遛狗被狗遛。越高级的概念，越要用越低级、越琐碎、越"不登大雅之堂"的日常场景去解释。反差越大，效果越炸。绝对禁止用"业界术语解释术语"或用同样抽象的比喻去解释抽象概念。

**识别锚点 vs 可变变量：**

- **识别锚点**（不可变）：手绘黑白线稿、荒诞表情、短句气泡、红色标注箭头、米白纸张、大留白、无分镜边框。
- **可变变量**（每次可调）：标题区形态、章节数量、阅读路径、中心比喻、人物身份、主题物件、物理草图、局部配色、底部总结形式。
- 每次生成前都要根据主题选择 2-4 个可变变量，不能无脑套同一套模板。

**御用主角参考图：** `{SKILL_DIR}/assets/nine-comic-character-ref.png`。使用提示词生成图片时，建议同时上传此参考图以确保人物风格统一。人物身份特征：黑框眼镜、略乱头发、表情夸张、穿白衬衫。角色定位：严肃又滑稽的"民间百科讲解员"。

---

## 角色判断标准（pass/fail 测试）

| 测试 | 通过 | 失败 |
|:---|:---|:---|
| 去掉主角测试 | 移除主角后画面失去核心趣味和视觉锚点——主角是画面的灵魂 | 移除主角后画面信息完整——主角只是装饰，需重做 |
| 辨识度测试 | 去掉黑框眼镜就不像同一个人——角色特征足够鲜明 | 换成普通火柴人画面无区别——角色特征不够，需强化眼镜/头发/表情描述 |
| 风格一致性测试 | 多页间主角看起来是同一个人 | 第3页的主角和第1页不像同一人——参考图未被使用或提示词角色描述不足 |
| 表情夸张测试 | 主角表情让读者不自觉地笑出声 | 主角一脸严肃地站在荒诞场景里——未显式写"表情夸张滑稽" |

## 工作流

### A1. 拆参考图

先把参考图拆成可转译的视觉语言：

- 版式：手机竖版长图，顶部横幅，中段分节，底部总结。
- 图像：黑色手绘线稿，表情夸张，人物比例略怪。
- 文案：对话式、标注式、短句，不堆长段落。
- 气氛：恶搞、古怪、反差，高深概念 + 低级比喻 = 笑点来源。
- 留白：漫画之间不用边框，用空白自然分隔。
- 颜色：米白纸张、青蓝标题栏、橙色气泡、少量红色箭头。

然后判断主题适合哪种信息形态，匹配"俗比喻"场景：

- 概念解释 → 荒诞课堂/标本图/解剖图/误区对照（菜市场摊位分类、泡面口味对比）
- 流程方法 → 路线图/传送带/维修工单/实验步骤（食堂打饭流程、快递分拣）
- 商业产品 → 柜台/仓库/账本/控制台/展台（菜市场砍价、自助餐策略）
- 心理行为 → 脑内小剧场/天平/拉扯绳/情绪仪表盘（纠结中午吃啥、拖延到最后一刻）
- 科学技术 → 物理草图/剖面图/电路图/管道流动（马桶冲水原理、WiFi为什么慢）
- 玄学命理 → 罗盘/天象图/日历页/古籍批注（老妈凭直觉判断你有没有感冒）

### A2. 把主题变成滑稽比喻

核心技法：**（高深概念）≈（菜市场/厕所/泡面级别的日常破事）**。

比喻取材原则：
- 从生活中最低处找：菜市场、公共厕所、泡面、外卖、地铁、马桶、晾衣服、遛狗、相亲、砍价、排队、快递、WiFi 断了、手机没电。
- 高级概念必须配低级比喻：讲"系统架构"就用"合租房的马桶堵了谁来通"；讲"投资组合"就用"自助餐怎么拿最划算"。
- 禁止"同行比喻"：不要用行业黑话解释另一个行业概念。

为抽象主题找两个具象比喻：一个表示"错误或混乱"，一个表示"正确或沉淀"。

**比喻实战参考：** 成功和失败的比喻案例及渲染问题修复，见 [nine-comic-metaphor-catalog.md](nine-comic-metaphor-catalog.md)。

### A3. 组织长图结构

先根据主题选择版式骨架：

1. **标准解释型**：标题 + 混乱场景 + 定义句 + 2-3 节解释 + 底部总结。
2. **对照拆解型**：左边"错误理解"，右边"正确理解"，中间穿插人物吐槽和标注箭头。
3. **路线流程型**：用弯曲路线、传送带或管道串起 4-6 个步骤。
4. **解剖标本型**：把主题画成机器、动物、账本、房子或器官剖面。
5. **实验黑板型**：用公式、草图、器材和失败实验解释机制。
6. **案例剧场型**：用 3-5 个连续荒诞小场景推进。

默认结构（可变，不要次次照抄）：

1. 顶部：标题「9号漫画：主题名」+ 副标题。
2. 开场：两段无边框漫画，展示混乱场景。
3. 中心句：一句定义或总论。
4. 第一节：外部方案/别人经验的好处与风险。
5. 第二节：自己的方案/沉淀方法。
6. 第三节：四步操作流程。
7. 底部：黑色墨块总结 + 一个荒诞收尾气泡。

每段之间"大面积留白、段间距明显拉宽、不要紧凑"。

**内容长度评估：** 若章节超过 5 节、流程步骤超过 6 步、需要同时展示多种版式、或预估高度超过 4000px，应拆分为多页（详见 `multi-page-handling.md`）。

### A4. 加入主题物件和物理草图

- 每张图至少 3-6 个与主题强相关的视觉物件。
- **反差物件优先**：高深概念优先用日常俗物来解释（"数据库索引"旁边画菜市场摊主用本子记"土豆在第三排"）。
- 物理草图要像手绘批注，不要像精密 CAD。
- 草图服务解释，不做装饰。每个草图旁边要有短标注。

### A5. 写提示词

按 [nine-comic-prompt-skeleton.md](nine-comic-prompt-skeleton.md) 模板填充提示词。写好后将完整提示词输出给用户，建议用户在生成图片时同时上传参考图 `assets/nine-comic-character-ref.png`。

## 配色方案

- 背景：米白纸张，轻微纸纹
- 主色：青蓝标题栏 + 橙色气泡 + 红色标注箭头
- 线条：黑色手绘线稿，粗细略不一
- 文字气泡：橙色 + 黑色手写字

## 提示词实战经验（风格 A）

以下是从实际生成中总结的硬经验，不遵守就会踩坑：

1. **[N4 机制] 必须显式写"表情夸张滑稽"**——图像模型默认画中性表情，不写就会得到一脸严肃的人站在荒诞场景里，喜剧效果全毁。关键句：「表情夸张滑稽，嘴巴张大，眼睛瞪圆」。
2. **[共享文字渲染规则] 手写批注要写"手写批注风格"而非"标注"**——"标注"会被模型理解为打印体标签，"手写批注风格"才能得到潦草的手写感。
3. **[N1 机制] "不要矩形边框"写两遍**——一遍在开头约束区，一遍在排版要求区。模型对负面约束有"只看一次就忘"的倾向，重复强调才有效。
4. **[共享主体一致性规则] 每次都要上传参考图**——不传参考图，人物风格必定漂移（眼镜没了、头发变了、表情不夸张了）。参考图是锚点，不是可选附件。
5. **[共享比例锚定规则] 比例必须写"约 720x2800"**——只写"竖版长图"模型会画成正方形或3:4；写"手机竖版长图"有时能触发正确理解，但加上具体像素数更保险。

## 风格 A 特有反馈

| 反馈 | 处理方式 |
|:---|:---|
| "边框太多" | 写「不要矩形边框、不要分镜框、不要卡片边框」 |
| "太挤" | 写「每段之间大面积留白，段间距明显拉宽，整体不要紧凑」 |
| "不够滑稽" | 增加荒诞比喻、夸张表情、反差吐槽 |
| "太模板" | 改版式骨架，改阅读路径、标题区、底部总结和主题物件 |
| "不够好笑/太正经" | 把比喻再降一级——从"公司管理"降到"菜市场大妈管摊位" |
| "比喻太高深" | 换成不识字的老太太也能秒懂的日常场景 |
| "人物风格不统一" | 在提示词开头强化人物特征描述，建议用户上传参考图 |
