# 共享机制（跨风格通用）

将跨 2 个以上风格都出现的实战经验抽到本文件，避免在每个风格章节重复。每个机制有编号（N1-N7）以便各风格实战经验引用。

---

## 通用生成哲学：抽奖，不是质检

**生成是廉价的；AI 自检是昂贵的且价值有限。人的品味才是质量关卡。**

不要试图一次性生成"完美"提示词。而是：

1. **并行生成多个候选**，全部展示给用户，不做预筛选
2. **让用户挑选**最接近意图的那个
3. **如果"差一点但不对"**，在用户选中的候选基础上微调，而不是放弃重来

各风格的候选策略：

| 风格 | 候选策略 |
|:---|:---|
| A: 9号漫画 | 核心比喻 2-3 候选 + 不同版式组合，全部展示让用户选 |
| B: 信息图 | 布局 + 信息分配 2 候选（如流程型 vs 对比型），让用户选方向 |
| C: 四格漫画 | 先为封面 + 第 1 页生成 2 个候选锁定视觉方向，确认后再批量生成剩余页面 |
| D: 线条人 | 核心比喻 2-3 候选（不同张力对比构图），全部展示让用户选 |
| E: 生活感人像 | 10 张全部出（不挑）；批次差异规则避免同质化，用户挑出对味的 |

**核心理念：宁可多生成 2 个让用户选，也不要花同样时间让 AI 自我审查。**

## 主体一致性控制（适用于有 IP 角色的风格 A/C/D/E）

任何带"固定角色 IP"的风格（A 讲解员 / C 三角色 / D 线条人 / E 网红）必须遵守：

1. **锚点描述写在提示词开头**——把角色身份特征放在第一段，让模型最先看到。
   - 风格A："黑框眼镜、略乱头发、表情夸张滑稽、穿白衬衫"
   - 风格D："极小的戴眼镜的线条小人……"
   - 风格E："一位极具镜头感的韩国 INS 网红，皮肤白皙，身材傲人"

2. **必须同时上传参考图**——参考图不是可选附件，是锚点。
   - 风格A 用 `assets/nine-comic-character-ref.png`
   - 其他风格暂未提供参考图，使用时建议根据主题生成 1 张锁定形象

3. **多页/多图生成时复用同一段 prompt 块**——不要每页重写一次。
   - 抽取 20-40 字的"角色锁定块"作为独立段落
   - 后续每张图只换场景描述，角色块完全复制

4. **首轮应生成 2-4 个候选形象让用户挑**——避免锁定一个方向后无法调整。

## 比例与版式锚定（所有风格通用）

**铁律：比例必须写"具体像素 + 方向描述"双锚定。**

| 句式 | 示例 | 效果 |
|:---|:---|:---|
| ❌ 不推荐 | "竖版长图" / "16:9" / "手机长图" | 模型自由发挥，常得正方形或近似比例 |
| ✅ 推荐 | "约 720x2800 竖版长图" / "1920x1080 横版" / "3:4 竖版（如 1080x1440）" | 模型更听话 |

**原因**：模型对"宽高比"的理解是模糊的，对"具体像素数"是精确的。两个一起写，模型按"上下界"画。

**每个风格的固定比例（速查表）：**

| 风格 | 比例 | 像素 |
|:---|:---|:---|
| A: 9号漫画 | 竖版长图 | 720x2800 |
| B: 信息图 | 16:9 横版 | 1920x1080 |
| C: 四格漫画 | 3:4 竖版 | 1080x1440 |
| D: 线条人 | 16:9 横版 | 1920x1080 |
| E: 生活感人像 | 3:4 或 4:5 竖版 | 1080x1440 或 1080x1350 |

## 文字/字体渲染通用规则（涉及画面文字的所有风格：B/D）

**句式统一**：写"用{笔}手写，{特征 1}，{特征 2}，{特征 3}，严禁{字体分类词}"

**关键句模板**：
- 钢笔 / 马克笔手写
- 字迹歪斜、大小不一
- 笔触顿挫、像便签随手写的
- 严禁打印体 / 电脑字体 / 宋体 / 黑体 / 等线体 / PPT 字体

**字数上限**：中文≤6 字（超过 6 字乱码/拆字/漏字几乎必然；超 8 字几乎必败）

**失败退路**：模型实在写不好时写 "no text, leave the corner blank"，后期用 Procreate / PS 叠加真实手写金句。

## 通用负面提示框架（N1-N7 机制速查表）

| 机制编号 | 机制 | 适用风格 | 标准句式 |
|:---|:---|:---|:---|
| **N1** | 核心禁止项要写两遍 | 所有 | "在开头约束区写一次 + 在排版要求区再写一次"（模型对负面约束"只看一次就忘"）|
| **N2** | 禁止类约束单写一句，不要嵌在描述中 | B/C/D/E | "单独一行 `不要 XXX`，不要用'避免 XXX' / 'not XXX' 软化" |
| **N3** | 核心 IP 标识要枚举禁止变体 | A/D | "方框眼镜，不要圆框、不要椭圆、不要菱形、不要加粗、不要墨镜、不要护目镜、不要鼻梁、不要镜腿"（≥6 个变体）|
| **N4** | 夸张/显眼特征要显式写出程度副词 | A/C/E | "表情夸张滑稽 / 嘴张大 / 眼睛瞪圆"——不写程度副词，模型画中性 |
| **N5** | 中文文本渲染用物理书写动作词 | B/D（凡涉及画面文字）| 钢笔/马克笔手写 + 字迹歪斜 + 大小不一 + 严禁"手绘字体" |
| **N6** | 中文文本≤6 字原则 | B/D | 超过 6 字乱码/拆字/漏字几乎必然 |
| **N7** | 后期叠加退路 | B/D | "no text, leave corner blank"，后期手写叠加 |

**风格使用说明**：每个风格章节的"实战经验"只引用机制编号 + 该风格的具体关键句，不再重复机制本身。

## 通用迭代规则（反馈 → 提示词开头加约束）

当用户提出反馈时，不要重写整个方向。把反馈变成更强的约束，放到下一版提示词**开头**。

| 反馈 | 处理方式 |
|:---|:---|
| "标题不对" | 提示词开头写「顶部标题必须写……，不要写……」 |
| "太像参考品牌" | 写「原创内容，不复制任何品牌名、logo、角色」 |
| "文字糊" | 减少长句，改短标题、短气泡、短标注 |
| "太空泛" | 增加行业物件、主题道具、机制草图 |
| "单页太长/放不下" | 评估是否拆分为多页（详见 `multi-page-handling.md`）|
| "肖像权风险"（仅风格 E）| 加写「不画成任何具体公众人物的相似脸」|

反馈按风格区分的更细粒度处理见 `feedback-by-style.md`。
